Let's dig into each stage.

Stage 1: Query Understanding

Not every question needs web search. Perplexity first classifies the query:

"What's 2+2?" → No search needed (model knowledge)

"What's the weather in Mumbai?" → Needs real-time data

"Latest on India's semiconductor plans?" → Needs web search + news

"Explain quantum computing" → Could use model knowledge, but search adds freshness

For queries that need search, Perplexity generates optimized search queries — not your original question, but what would find the best results:

User query: "What's the latest on India's semiconductor fab plans?"

Generated search queries:

  1. "India semiconductor fabrication plant 2024 latest news"
  2. "India chip manufacturing Tata Micron factory update"
  3. "India semiconductor policy ISMC fab"

Multiple queries are generated to maximize coverage. Each targets a different angle of the topic.

🔧

The Perplexity Index

Beyond real-time crawling, Perplexity has built a massive pre-crawled index:

Billions of web pages pre-crawled and indexed

Updated continuously — news sources crawled every few minutes

Domain quality scoring — authoritative sources ranked higher

Structured extraction — not just text, but tables, lists, dates

This pre-crawled index is why Perplexity can answer in 3 seconds instead of 30. Most of the crawling is already done.

The reranking step is crucial. Embedding similarity is fast but rough. A cross-encoder (a model that takes query + passage as input and outputs a relevance score) is slower but much more accurate. Perplexity uses both: embeddings for fast initial filtering, cross-encoder for precise reranking.

Ranking Factors

Relevance score:

40% - Semantic relevance (does the passage answer the question?)

25% - Recency (newer = better for current topics)

20% - Source authority (established media > random blog)

15% - Passage quality (length, specificity, factual density)

The Citation Verification Problem

Generating citations is easy. Generating correct citations is hard.

Common failure modes:

  1. "Ghost citation" — [3] doesn't actually support the claim

"India plans to build 10 fabs by 2025 [3]"

→ Source [3] never mentions "10 fabs" or "2025"

  1. "Hallucinated synthesis" — combining facts from different sources incorrectly

"Tata is building a $2.75 billion fab in Karnataka"

→ Tata is building a fab [1], $2.75B is Micron [2], Karnataka is ISMC [4]

  1. "Outdated citation" — citing old information when newer exists

Perplexity addresses this with:

Perplexity Pro: The "Deep Research" Mode

Perplexity Pro's research mode is more sophisticated — it runs multiple search-read-think cycles:

Cycle 1: Initial search

→ "India semiconductor plans"

→ Read top results

→ Identify gaps: "Who are the specific companies? What timelines?"

Cycle 2: Follow-up search

→ "Tata semiconductor fab timeline India"

→ "Micron Gujarat facility progress 2024"

→ Read, extract new information

Cycle 3: Deep dive

→ "India semiconductor policy PLI scheme details"

→ "ISMC Karnataka 65nm fab latest update"

→ Synthesize all gathered information

Final: Generate comprehensive answer with all sources

This iterative approach — search, read, identify gaps, search again — is essentially agentic RAG (Episode 30 meets Episode 22). The model is acting as a research agent, deciding what to search for next based on what it's already found.

The Answer Engine vs Search Engine Debate

Perplexity represents a fundamental shift:

Google (Search Engine) Perplexity (Answer Engine)

Output Links to pages Direct answer with citations

User workClick, read, synthesizeRead the answer
FreshnessExcellent (massive crawl)Good (smaller crawl)
Revenue modelAds ($200B+/year)Subscription ($20/mo)
AccuracyUser verifiesMust be accurate (or trust is lost)
Publisher impactSends trafficAbsorbs traffic (controversial)

The publisher problem is real. If Perplexity answers your question so well that you never click through to the source, what incentive do publishers have to create content? This is an unsolved tension.

Practical Takeaways

Perplexity is RAG at web scale — the same pattern from Episode 22, but with live web search as the retrieval source

Query optimization matters — transforming user questions into effective search queries is a crucial step

Reranking > embedding similarity — cross-encoders are slower but dramatically more accurate

Citation verification is its own pipeline — generating citations is easy, verifying them is hard

Iterative search (agentic RAG) beats single-shot — search, read, identify gaps, search again

The answer engine model changes the web's economics — if users don't click through, publishers lose traffic
