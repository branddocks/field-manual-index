Everyone has an opinion on agent frameworks. "LangChain is bloated." "CrewAI is magical." "Just write raw API calls." "AutoGen is the future."

Here's the truth: every framework does the same thing — LLM + tools + loop. What differs is how much abstraction they add, how they handle multi-agent orchestration, and how much they fight you when you need something custom.

Let's open the hood on each one.

What Agent Frameworks Actually Do

Strip away the branding and docs, and every framework provides:

Tool registration — Define functions the LLM can call

The agent loop — Run think → act → observe repeatedly

Message management — Handle conversation history

Error handling — Retry failed tool calls, handle parsing errors

Orchestration — Coordinate multiple agents (some frameworks)

That's it. If you can build those five things yourself in 100 lines of Python, do you need a framework? Maybe. Depends on how complex your agents get.

⚡

LangChain

The OG. The one everyone has opinions about.

LangChain was the first major agent framework (2022). It tries to be everything — chains, agents, memory, retrieval, output parsing, callbacks, streaming. This ambition is both its strength and its biggest criticism.

Architecture

LangChain Stack:

├── langchain-core # Base abstractions (Runnables, messages)

├── langchain # Chains, agents, retrieval

├── langchain-community # Third-party integrations

├── langchain-openai # OpenAI provider

├── langchain-anthropic # Anthropic provider

├── langgraph # Graph-based agent orchestration

└── langsmith # Observability & tracing

Pros Cons

Massive ecosystem, integrations for everythingAbstraction overload — too many layers

Skip when: You're building a simple single-agent tool caller. The overhead isn't worth it.

CrewAI

Multi-agent made simple.

CrewAI's pitch: define agents as "crew members" with roles, give them a mission, and let them collaborate. It's the most intuitive multi-agent framework.

Architecture

CrewAI Concepts:

├── Agent → A persona with role, goal, backstory, tools

├── Task → A specific assignment for an agent

├── Crew → A team of agents working on tasks

├── Process → How tasks are executed (sequential, hierarchical)

└── Tools → Functions agents can use

AutoGen (Microsoft)

The academic powerhouse.

AutoGen is Microsoft's framework focused on multi-agent conversations. Its key idea: agents communicate through natural language conversations, and you define the rules for who speaks when.

Architecture

AutoGen Concepts:

├── ConversableAgent → Base agent that can chat

├── AssistantAgent → LLM-powered agent

├── UserProxyAgent → Human-in-the-loop or auto-executor

├── GroupChat → Multi-agent conversation

└── GroupChatManager → Controls turn-taking in group chat

Pros Cons

Natural conversation-based collaborationConversations can meander and waste tokens

Skip when: You want predictable, fast pipelines. AutoGen conversations can be verbose and expensive.

Smolagents (Hugging Face)

The minimalist.

Smolagents is Hugging Face's answer to framework bloat. Its philosophy: agents should be simple, transparent, and easy to understand. The entire agent loop is ~200 lines of code.

Architecture

Smolagents Concepts:

├── ToolCallingAgent → Standard tool-calling agent

├── CodeAgent → Writes and executes Python code as actions

The CodeAgent Difference

Smolagents' CodeAgent is unique — instead of generating JSON tool calls, it writes Python code as its action:

python

Standard tool calling (other frameworks):

Action: search(query="latest Python version")

Smolagents CodeAgent:

The agent writes actual Python code:

snippet
code
results = web_search("latest Python version 2025")
version = results[0]["title"].split("Python ")[1]
print(f"Latest version: {version}")

This is more flexible — the agent can use variables, loops, conditionals, and string manipulation directly. No need to create a tool for every little operation.

Verdict

Pros Cons

Dead simple, easy to understandFewer integrations
CodeAgent is genuinely innovativeSmaller community
Minimal dependenciesLess battle-tested in production
Transparent — you can read the entire sourceLimited orchestration for multi-agent

Use when: You want simplicity and transparency. Great for learning, prototyping, and when you want to understand exactly what your agent is doing.

Skip when: You need complex multi-agent orchestration or extensive third-party integrations.

When to Skip Frameworks Entirely

Sometimes the best framework is no framework:

python

A complete agent in 40 lines, no framework

from openai import OpenAI

import json

snippet
code
client = OpenAI()
tools = [...]  # Your tool definitions
def run_agent(task, max_steps=15):
messages = [
        {"role": "system", "content": "You are a helpful agent. Use tools to complete tasks."},
        {"role": "user", "content": task}
    ]
for _ in range(max_steps):
        response = client.chat.completions.create(
            model="gpt-4o", messages=messages, tools=tools
        )
        msg = response.choices[0].message
        messages.append(msg)
if not msg.tool_calls:
            return msg.content
for tc in msg.tool_calls:
            result = execute_tool(tc.function.name, json.loads(tc.function.arguments))
            messages.append({"role": "tool", "tool_call_id": tc.id, "content": str(result)})
return "Max steps reached"

Use raw API when:

Your agent is simple (1-3 tools, single agent)

You want full control over every decision

Framework abstractions are getting in your way

You're optimizing for cost or latency

Use a framework when:

Multi-agent coordination

Complex state management

You need built-in error handling and retries

Your team needs shared conventions

🛡️

Practical Takeaways

All frameworks do the same thing — LLM + tools + loop, with varying abstraction levels

LangGraph for complex workflows — the most powerful orchestration, but steep learning curve

CrewAI for role-based teams — intuitive, fast to prototype, great for content pipelines

AutoGen for iterative discussion — agents that argue and refine, good for code review

Smolagents for simplicity — minimal, transparent, great for learning

Raw API for simple agents — 40 lines of code beats a framework when your needs are simple
